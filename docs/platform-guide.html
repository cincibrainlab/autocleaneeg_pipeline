01 — The Problem

Eighty percent of EEG research is janitorial work

Every neuroscience lab has the same story. A graduate student records 200 sessions of resting-state EEG. Then spends six months cleaning it—file by file, channel by channel, epoch by epoch—before the real science can begin.

"We recorded 300 pediatric EEGs over two years. I spent the next year just getting them into a state where I could run a single analysis."

The problem isn't that the tools don't exist. MNE-Python is extraordinary. AutoReject works. ICLabel classifies. The problem is orchestration. Every lab writes their own pipeline scripts. Every postdoc reinvents the wheel. Parameters drift between subjects. Someone forgets the notch filter. The intern uses a different reference. And six months later, you're debugging your preprocessing instead of writing your paper.

AutoCleanEEG is the answer to one question: what if cleaning EEG data were as simple as dropping files into a folder?

02 — How It Works

Three ideas, one platform

AutoCleanEEG combines a modular processing engine, a task-based configuration system, and a file-watching automation server into a single, cohesive platform.

Engine

Processing Blocks

Sixteen modular blocks—filtering, resampling, bad channel detection, ICA, artifact rejection, epoching—snap together like Lego bricks. Each block is a tested, versioned unit. You compose pipelines by listing which blocks to run and in what order.

Config

Task Files

A "task" is a Python file that declares your processing recipe: which montage, which filter settings, which ICA method, which epoch window. One file per paradigm. Share it with your lab. Version it in Git. Never wonder "what parameters did we use?" again.

Automation

Serve

The Serve system watches your input folders. When a new EEG file appears, it matches it to a route, queues it for processing, runs your task file, and writes BIDS-compliant outputs with PDF quality reports. You can monitor everything from a web dashboard or the terminal.

Quality

Reports & Review

Every processed file generates a PDF report with raw-vs-cleaned overlays, ICA component topographies, PSD plots, and a full metadata audit trail. A built-in review workflow lets you mark files as Pass, Fail, or Review with keyboard shortcuts—just like reviewing papers.

03 — The Pipeline

What happens inside one processing run

When a resting-state EEG file hits the queue, here's the journey it takes through the engine. Every step logs metadata, and any step can be enabled, disabled, or reconfigured via your task file.

Import Raw
Load .set, .edf, .bdf, .fif, or .vhdr files via MNE. Extract metadata: channel count, sample rate, duration, event markers.
Resample
Downsample to target rate (typically 250 Hz) for consistent processing and smaller file sizes.
Filter
Bandpass (e.g., 1–80 Hz) and notch (60/120 Hz) filtering to remove drift and powerline noise.
Drop Outer Layer & Assign EOG
Remove edge electrodes (for dense arrays like HydroCel-129). Mark electrodes near the eyes as EOG channels.
Trim & Crop
Remove recording edges with setup artifacts. Optionally crop to a target duration (e.g., first 5 minutes).
Bad Channel Detection
Automated detection via PREP pipeline (RANSAC, correlation, deviation). Flagged channels are interpolated from neighbors.
Re-reference
Apply average reference (or specified reference scheme) for consistent voltage baselines.
Artifact Annotation
Three passes: noisy epochs, uncorrelated epochs, and dense oscillatory artifacts. Marks bad segments without removing data.
ICA Decomposition
Run Infomax or PICARD ICA. Automatically classify components with ICLabel: brain, eye, muscle, heart, noise.
Component Rejection
Remove non-brain components (eye blinks, muscle, heartbeat) while preserving neural signal. Generate component report PDF.
Epoching
Segment continuous data into fixed-length epochs (resting state) or event-locked windows (ERP/ASSR). Reject bad epochs.
Export & Report
Save cleaned data as BIDS-compliant .set/.fif. Generate PDF report with PSD plots, raw-vs-cleaned overlay, ICA topographies, and full metadata JSON.
04 — Five Scientists, Five Problems

Real work, real pipelines

Every lab has different paradigms, different hardware, different questions. Here's how five researchers use the same platform for very different science.

🧠
The Developmental Neuroscientist
Screening 400 children for autism biomarkers

Dr. Reyes runs a longitudinal study at a children's hospital. Every week, 8–12 kids aged 3–8 come in for resting-state EEG with a 128-channel HydroCel geodesic net. Her research question: can spectral power patterns in alpha and gamma bands predict autism severity scores?

The challenge: Pediatric EEG is noisy. Kids move. They cry. They pull electrodes off their heads mid-session. Her previous pipeline required a trained RA to manually reject bad channels and epochs for each file—about 45 minutes per recording. With 400 subjects, that's 300 hours of human labor just on preprocessing.

Her setup: She created a single task file called RestingEyesOpen.py specifying her HydroCel-129 montage, 1–80 Hz bandpass, aggressive outer-layer removal (the peripheral electrodes are always bad on squirmy kids), and ICLabel-based artifact rejection. She configured one route in the Serve dashboard that watches her /data/incoming/resting/ folder.

The workflow: After each recording session, the EEG tech exports the .set file and drops it into the incoming folder. AutoCleanEEG picks it up within seconds. Twenty minutes later, a cleaned dataset and PDF report appear in the output directory. At the end of each week, Dr. Reyes opens the Results page, scans the reports, and uses the Pass/Fail/Review workflow to flag any sessions that need a second look. The ones that pass go straight into her spectral analysis pipeline.

# RestingEyesOpen.py — Pediatric resting state config = { "montage": {"value": "GSN-HydroCel-129"}, "resample": {"value": 250}, "filtering": {"value": {"l_freq": 1.0, "h_freq": 80.0, "notch_freqs": [60, 120]}}, "drop_outerlayer": {"enabled": True}, "ICA": {"value": {"method": "infomax"}}, "epoch_settings": {"value": {"tmin": 0, "tmax": 2.0}}, }
🎵
The Auditory Neuroscientist
Analyzing 40 Hz ASSR responses across genotypes

Dr. Chen studies auditory steady-state responses (ASSR) in a Fragile X mouse model, but the same paradigm runs in his human lab too. His 40 Hz click-train stimulus produces a characteristic neural oscillation that's weaker in certain genetic conditions. He needs event-locked averaging, not resting-state epochs.

The difference: His task file uses epoch_with_event_id instead of epoch_continuous_data. The config specifies event codes (stimulus onset = 1, response = 2) and a −0.5 to 1.0 second epoch window. The pipeline locks each epoch to the stimulus trigger, rejects bad trials, and averages across the remaining clean epochs.

Why automation matters: He runs the same paradigm across three sites. Each site has different hardware (BioSemi 64 at one, HydroCel-128 at another, standard 10-20 at the third). He has three task files with identical processing parameters but different montage settings. Three routes, three folders, one dashboard. Cross-site consistency without cross-site headaches.

He uses the Event Analyzer page to verify trigger timing before committing a file to the full pipeline. The inter-stimulus interval histogram tells him immediately if the stimulus computer had timing jitter during a session.

📊
The Clinical Research Coordinator
Processing overnight EEGs for a seizure study

Maria isn't a programmer. She's the research coordinator for a multicenter epilepsy trial. Every morning, she downloads overnight EEGs from three hospital sites. Her PI needs clean data in BIDS format by the weekly team meeting.

Her entire workflow: Open the AutoClean Serve dashboard in her browser. Drag the new .edf files into the watched folder on the shared drive. Watch the Queue page as files turn from pending to processing to processed. If one fails (corrupted file, wrong montage), the error appears right in the dashboard—she emails the site to re-send it.

She doesn't need to know what ICA is. She doesn't need to open a terminal. The task file was written once by the study's signal processing consultant. Maria just moves files and reviews results. On the Results page, she uses keyboard shortcuts—P for Pass, F for Fail—to fly through 30 recordings in ten minutes. The decisions export as a CSV that goes straight into the study's REDCap database.

🔬
The Methods Developer
Benchmarking a new artifact rejection algorithm

Kai is a postdoc developing a novel wavelet-based artifact detector. They need to run 500 files through two pipelines—the standard one and their experimental one—and compare output metrics.

The power of task files: Kai created two tasks: Resting_Standard.py and Resting_WaveletExperimental.py. Both are identical except one uses the standard artifact annotation blocks while the other swaps in Kai's custom wavelet thresholding step. Two routes, same input folder, two output directories.

The automation server processes every file twice. Kai downloads the metadata JSON from both runs and compares: channels rejected, epochs surviving, ICA components removed, spectral power in the cleaned output. All 500 comparisons are done by Friday. The CSV export from the Results page becomes Table 2 in their methods paper.

🏥
The Lab Director
Running a 24/7 clinical EEG processing service

Dr. Pedapati directs a translational neuroscience lab. His team runs EEG on clinical trial participants, research subjects, and animal models. The data comes from multiple studies, multiple paradigms, multiple hardware systems. He needs the whole operation to run unattended.

The production setup: AutoClean Serve runs on a dedicated Mac Mini in the server closet. Seven routes handle different study arms: resting-state with HydroCel-129, ASSR with BioSemi-64, MMN with standard 10-20, and four others. Each route watches a different subfolder on the hospital's shared drive. The service runs in live mode with the file watcher enabled, processing new files within minutes of arrival.

Remote access: He clicks Share in the dashboard and configures a permanent Cloudflare Tunnel—a one-time setup with a free Cloudflare account that gives his lab a stable URL like https://eeg-lab.cchmc-brain.com. Unlike the ephemeral quick tunnels used for demos (which die on restart and change their URL every time), the named tunnel persists forever. The token is stored in the workspace, so it survives server reboots, OS updates, and machine migrations.

The postdoc in building A, the graduate student working from home, and the collaborator at another university all bookmark the same URL. They log in with a session password (auto-generated, shown in the Share popover) and can see the queue, check results, and review outputs in real time. The test/live mode toggle means new task configurations can be validated on sample data before being promoted to production.

Every processed file gets a full audit trail: SHA-256 hash of the input, all processing parameters, timestamps, software versions. When the FDA auditor asks "how was this data processed?", the answer is a single JSON file.

05 — The Dashboard

Ten pages. Everything you need.

The Serve web interface is designed for clinical operators and researchers who want to manage processing without touching a terminal.

Home

Dashboard

System health at a glance: active routes, queue depth, service status. Smart recommendations guide you to the next action—"Start the service" or "Review 3 failed jobs."

Config

Routes

Define which folders to watch, which file patterns to match, which task and montage to apply. Create routes with a form, promote from test to live with one click.

Monitor

Queue

Real-time view of every file in the system: pending, processing, done, failed. Click any entry to see full details and error messages. Retry failed jobs in bulk.

Control

Service

Start and stop the processing engine. View live logs streaming in real time. Configure advanced settings: cycle limits, idle timeout, sentinel file requirements.

Library

Tasks

Browse installed and available processing tasks. View the full pipeline as a flowchart or read the source code. Install from the library or create custom tasks.

Reference

Montages

Visual browser for all 30+ electrode configurations. See channel positions on a 2D topographic map, 3D coordinates, landmark positions, and which tasks are compatible.

Analysis

Results

Browse all processed runs with sorting, filtering, and search. Dive into any run for metrics, ICA components, PSD plots, event analysis, and raw metadata. Download artifacts as ZIP or export summaries as CSV.

QC

Review Decisions

Built into Results: mark each run as Pass, Fail, or Review using keyboard shortcuts (P/F/R). Add notes. Export decisions as CSV for your study database. Process 30 files in 10 minutes.

Inspect

Event Analyzer

Point at any raw EEG file and instantly see its event markers: types, counts, timing, inter-stimulus intervals, gaps, and transitions. Catches stimulus computer problems before you commit to processing.

Share

Persistent Tunnels

Share your dashboard with a single click. Quick tunnels for instant demos, or configure a permanent Cloudflare Tunnel with a free account for a stable URL that survives restarts. Token stored locally in the workspace—one-time setup, works forever. Session passwords protect every connection.

Settings

Settings & Setup

YAML configuration with syntax highlighting and live validation. Workspace picker for switching between studies. Guided tutorial walks new operators through the complete workflow in two minutes.

Two ways to share: instant demos vs. permanent access

Every AutoClean dashboard has a Share button in the top bar. Click it, and your local server becomes accessible from anywhere in the world over HTTPS—no port forwarding, no firewall rules, no IT tickets.

Quick Tunnel (zero config): Click Share and you get an instant *.trycloudflare.com URL. No account needed. Perfect for a quick demo or helping a colleague debug a failed run. The catch: the URL is random, changes every time you restart, and dies when the server stops. This is Cloudflare's free ephemeral mode—great for one-off sharing, not for bookmarks.

Named Tunnel (permanent, still free): For labs that need a stable URL their team can bookmark, click "Configure permanent tunnel" in the Share popover. The one-time setup takes three minutes:

Create a free Cloudflare account

No credit card. Go to one.dash.cloudflare.com.

Create a tunnel

Networks → Tunnels → Create. Name it anything (e.g., eeg-lab). Set the service to http://localhost:8000.

Copy the token, paste into AutoClean

The token and your tunnel's public URL go into the config form. Saved to tunnel_config.json in your workspace—never leaves your machine.

From then on, clicking Share starts your named tunnel with the same URL every time. The dashboard shows a green "Permanent" badge instead of the cyan "Temporary" one. Your team bookmarks one URL. It works today, next week, and after the next OS update.

06 — Hardware Compatibility

Your electrodes. Your format.

AutoCleanEEG supports the electrode systems and file formats used by the majority of research and clinical EEG labs worldwide.

Electrode Systems

HydroCel Geodesic

32, 64, 65, 128, 129, 256, 257 channels. The workhorse of developmental neuroscience.

BioSemi ActiveTwo

16, 32, 64, 128, 160, 256 channels. Standard in many auditory and cognitive labs.

Standard 10-20 / 10-05

The international electrode placement systems. Compatible with virtually any EEG amplifier.

EasyCap, EGI, MGH

Specialty systems including EasyCap M1/M10, EGI 256, and MGH 60/70 layouts.

File Formats

.set (EEGLAB) · .edf / .bdf (European Data Format / BioSemi) · .fif (MNE-Python native) · .vhdr (BrainVision). All read natively via MNE-Python with full metadata preservation.

07 — Getting Started

From zero to first processed file

Whether you prefer the terminal or the browser, here's the fastest path to your first cleaned dataset.

Install the package

pip install autocleaneeg-pipeline — pulls MNE, ICLabel, AutoReject, FastAPI, and all dependencies. Python 3.11–3.13 supported.

Launch the dashboard

autocleaneeg-serve --port 8000 --path ~/eeg-workspace — creates a workspace directory, starts the web server, opens your browser.

Run the tutorial

Click the Tutorial button in the sidebar. The 2-minute guided walkthrough creates a sample route, deploys the configuration, starts the service, and processes a sample file. You'll see every step of the system in action.

Create your first route

On the Routes page, click New Route. Pick your task file (start with a built-in like RestingEyesOpen), select your montage, point it at your data folder, and click Create. Deploy the config from Settings.

Drop in a file

Copy an EEG file into your watched folder. Watch the Queue page. Within minutes, you'll have a cleaned dataset and a PDF report in your output directory.

Review the results

Open the Results page. Click into your run. Browse the summary metrics, PSD plots, ICA component report, and event analysis. If it looks good, hit P for Pass.

Or use the CLI

Everything the dashboard does is available from the command line. Process a single file, manage routes, browse tasks—all without a browser.

# Process a single file directly $ autocleaneeg-pipeline process \ --task RestingEyesOpen \ --file ~/data/subject_001.set # Inspect events before processing $ autocleaneeg-pipeline events analyze ~/data/subject_001.set # List available tasks and montages $ autocleaneeg-pipeline task list $ autocleaneeg-pipeline montage list
08 — Under the Hood

A platform, not a script

AutoCleanEEG is structured as a proper software system with clear boundaries between the processing engine, the automation layer, and the user interface.

Core

Processing Engine

Mixin-based architecture. Each processing step (filtering, ICA, epoching) is a separate module that can be composed into arbitrary pipelines. Functions are pure and stateless. Metadata is accumulated through a pipeline context object.

Automation

Serve Layer

FastAPI web server + file watcher + job queue. Routes define folder→task mappings. Files are discovered, hashed, queued, processed, and archived with full provenance tracking. Test/live mode separation prevents untested configs from touching real data.

Interface

Web Dashboard

React 19 + Tailwind CSS + Vite. Ten pages covering every operational need. Polls the API for real-time updates. Fully functional in a browser—no local Python environment needed for operators.

Data

Output Format

BIDS-compliant directory structure. SQLite run database for fast querying. JSON metadata sidecar per run. PDF reports with visualizations. SHA-256 hashing for integrity verification. CSV decision exports.

Key dependencies: MNE-Python 1.10 for signal processing, MNE-ICLabel 0.8 for component classification, AutoReject 0.4 for epoch rejection, PREP pipeline (PyPREP) for bad channel detection, FastAPI for the web API, React 19 for the dashboard, and PyMuPDF for PDF report rendering.
