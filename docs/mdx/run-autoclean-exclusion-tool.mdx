# AutoClean Inclusion/Exclusion Review Run Log

<Steps>
  <Step title="Anchor the experience to autoclean_review">
    I loaded the existing <code>autoclean_review</code> Qt widget and extended it instead of rewriting the interface. This keeps the wide MNE browser, manual epoch rejection controls, and run-record viewer exactly as users remember them while letting the new helper inherit file-tree wiring, status bar updates, and dependency guards.
  </Step>
  <Step title="Layer decision tracking on top of the familiar UI">
    After the base widget bootstraps, I inject a decision panel (Pass/Fail/Review buttons with keyboard shortcuts), a live summary table, and a detail pane that holds reviewer notes plus clickable related exports/reports. Every selection updates a JSON-backed record keyed by the relative file path so autosaves can recover prior work.
  </Step>
  <Step title="Provide a lightweight CLI and sensible defaults">
    Use <code>autocleaneeg-pipeline exclude</code> to launch the GUI. It resolves <code>./exports</code> when available, or falls back to the working directory. Optional flags allow pointing at a specific exports directory or task root so the related-files browser can surface figures from <code>reports/</code>. Launching the command opens the maximized review window immediately.
  </Step>
</Steps>

## Interface Highlights

<Diagram name="How the exclusion helper builds on the review tool">
autoclean_exclude.main()
  -> determine_paths(args)
  -> run_autoclean_exclusion_tool(exports, task_root)
      -> ExclusionFileSelector(__init__)
          -> super().__init__(exports)  # original autoclean_review layout + MNE browser
          -> _extend_ui()  # decision buttons, summary table, notes pane, related files list
          -> _load_decisions()  # JSON/CSV autosave hydrated into the tree
          -> loadFiles()  # tree items recolored based on Pass/Fail/Review state
</Diagram>

<Callout type="tip" title="Keyboard flow">
  Press <strong>P</strong>, <strong>F</strong>, or <strong>R</strong> to set the decision for the active <code>.set</code>. The tool writes <code>autoclean_exclusion_decisions.json</code> and <code>autoclean_exclusion_decisions.csv</code> after every change, so you can quit and resume later without manual saves.
</Callout>

## How to Reproduce the Run

<Steps>
  <Step title="Install GUI extras (first time only)">
    <code>pip install autocleaneeg-pipeline[gui]</code>
  </Step>
  <Step title="Launch the helper">
    <code>autocleaneeg-pipeline exclude</code><br />
    The command picks <code>./exports</code> if present; otherwise it opens the current directory. Use <code>--exports</code> or the folder picker to change roots.
  </Step>
  <Step title="Review each export">
    Click a <code>.set</code> file, hit “Review Selected File” to open the full-screen timeseries browser, and decide with <code>P</code>/<code>F</code>/<code>R</code>. Add free-form notes in the right-hand pane, and double-click any related export/report to open it externally.
  </Step>
  <Step title="Inspect persisted decisions">
    Look beside the exports directory for <code>autoclean_exclusion_decisions.json</code> and <code>autoclean_exclusion_decisions.csv</code>. Each row records the relative path, decision, notes, and last-updated timestamp so collaborators can audit the review.
  </Step>
</Steps>

## Notes & Concerns

<Note>
  Deep directory scans for related reports are limited to <code>reports/</code> under the provided task root to keep lookups responsive. If your lab stores figures elsewhere, adjust the helper or supply a different root path.
</Note>

<Callout type="warning" title="Manual epoch edits still apply">
  Because the helper subclasses <code>autoclean_review</code>, “Save Edits” continues to write post-edit <code>.set</code> files. Make sure to finish any manual epoch rejection before flipping to the next export so the decisions and saved data stay synchronized.
</Callout>
