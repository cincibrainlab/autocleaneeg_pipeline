AutoClean with Docker
=====================

This page covers the current Docker story for this repository.

Current Status
--------------

AutoClean does not currently ship a single canonical Docker workflow for the
base CLI. The maintained container-oriented surface in this repo is the Serve
workspace export generated by the Serve tooling.

Use Docker here when you want to package a prepared Serve workspace for API and
worker deployment, not as the primary getting-started path for everyday local
CLI usage.

Recommended Local Workflow
--------------------------

For local development and most operator workflows, use the normal install path:

.. code-block:: bash

   uv tool install autocleaneeg-pipeline
   autocleaneeg-pipeline serve workspace --mode new --path /path/to/workspace
   autocleaneeg-serve up

Serve Workspace Docker Outputs
------------------------------

When you bootstrap a Serve workspace, the project can generate deployment
artifacts such as Dockerfiles and compose files under the workspace. Those
artifacts are tied to the specific workspace and mode you configured.

Before using them:

1. Create or select a Serve workspace.
2. Validate the route configuration.
3. Deploy the mode-specific Serve config.
4. Review the generated runtime files in the workspace before using them in
   your environment.

Example commands:

.. code-block:: bash

   autocleaneeg-pipeline serve workspace --mode new --path /path/to/workspace
   autocleaneeg-pipeline serve validate --path /path/to/workspace --mode test
   autocleaneeg-pipeline serve deploy --path /path/to/workspace --mode test

Boundaries
----------

- Docker is an operational deployment path, not the canonical install path for
  first-time users.
- Redis/RQ-backed Serve deployments are optional and may require environment-
  specific configuration.
- Review the generated workspace runtime files rather than assuming an old
  generic ``docker build`` flow applies to this repo.
